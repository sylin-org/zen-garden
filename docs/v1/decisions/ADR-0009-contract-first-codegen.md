# ADR-0009 — Contract-first codegen: the faces table is generated truth

**Status:** Accepted · 2026-08-28 (implements charter bet B1)
**Supersedes:** nothing whole; **operationalizes** L1 (one wire contract,
generated everywhere), R4.3 (the contract is generated truth), R4.7 (stale
truth is a build failure), R4.8 (surface degrees decided once)
**Referenced by:** `garden_contract::faces` (the table), `surface.json`
(the emitted artifact), `resolvers/node` (the first generated-language
consumer), rake's front-door and contract-vs-rake verification tests

## Provenance

B1 exists because the PoC bled from hand-maintained surfaces: 281 route
registrations, a manifest advertising 27 paths (7 of them ghosts that 404'd),
~195 unadvertised routes, three error shapes, and a 121-method hand-rolled
client. The `rake api` class of bugs — help lying about syntax, advertised
paths that fail parsing — was the natural product of three hand-maintained
sources of truth.

## Decision

The **face table is data in the contract crate** (`garden_contract::faces`):
the `Face` enum, and `FACES` — every face's wire verb, path template, and
summary, in one declared table. Everything else derives from it:

1. **The moss** routes from the table and renders its front door from it;
   its http.rs owns only the handler wiring (behavior vs declaration
   separated). A face not in the table must not exist anywhere.
2. **`surface.json`** — faces plus JSON Schemas of the wire-visible types
   (schemars-derived FROM the types, so type and schema cannot drift) — is
   generated by a test and committed as the repo's public contract
   artifact. The staleness gate is R4.7 mechanical: a type change without
   regeneration fails the suite; regenerate with `ZG_REGEN_SURFACE=1`.
3. **Clients verify against the table**: rake's path builders are checked
   against `FACES` in tests; the moss's compiled-in copy of `surface.json`
   is compared against the generated one.

## Law encoded

CODE-RULES **R4.3** operationalized: the contract is generated truth — a
type or face changed without regenerating `surface.json` fails the build.
The Slice Mandate's gate 5 (verdicts) applies to any NEW face: a face lands
with its table row, its handler wiring, and its schema in one commit.

## Alternatives considered

- **IDL-first** (OpenAPI YAML as the source, Rust generated) — rejected:
  the domain types are idiomatic Rust; generating them from YAML fights
  the language and orphans the contract crate (R0.3's dependency direction
  runs contract ← domain, not schema ← domain).
- **Hand-written schema with CI diff** — rejected: reintroduces the exact
  drift surface being killed; schemars derives schema from the same types
  the serializers use.
- **Per-surface hand-rolled clients** (the PoC's StoneApi, 121 methods) —
  rejected: every method re-implemented path/parse/error by hand; the
  v1 dispatcher (R4.8) + face-table verification replaces the class.

## Consequences

- The Node resolver v0 consumes the wire shapes as a generated/stable
  artifact; future resolvers (Python, MCP) consume the same `surface.json`.
- Adding a face is one `FaceDef` row + one handler arm + tests — the
  compiler and the bijection test demand the rest.
- The moss binary compiles `surface.json` in (`include_str!`), so any moss
  can serve its own full contract without touching the filesystem.
