# Automation Guide

Garden-Rake provides automation-friendly output modes for scripting and CI/CD integration.

## Global Flags

These flags work with most commands:

| Flag | Description |
|------|-------------|
| `--output json` | Machine-readable JSON output |
| `--output human` | Human-readable output (default) |
| `--field <path>` | Extract a single value using dot notation |
| `-q` / `--quiet` | Suppress hints and decorative output |

## The `config` Command

The `config` command is designed specifically for automation scenarios. It retrieves detailed configuration for a running service.

```bash
# Human-readable output
garden-rake config mongodb

# JSON output
garden-rake config mongodb --output json

# Extract just the connection URI
garden-rake config mongodb --field connection.uri

# Extract the port number
garden-rake config mongodb --field connection.port
```

### Output Structure

```json
{
  "name": "mongodb",
  "offering": "mongodb",
  "version": "mongodb",
  "status": "running",
  "health": "unknown",
  "stone": {
    "name": "oak",
    "endpoint": "http://10.0.0.5:7185"
  },
  "connection": {
    "uri": "mongodb://oak.local:27017",
    "uris": [
      "mongodb://oak.local:27017",
      "mongodb://10.0.0.5:27017"
    ],
    "hostname": "oak.local",
    "ip": "10.0.0.5",
    "port": 27017,
    "protocol": "mongodb"
  },
  "ports": {
    "native": 27017
  }
}
```

## Field Extraction

The `--field` flag uses dot notation with array indexing support:

| Path | Description |
|------|-------------|
| `name` | Top-level field |
| `connection.port` | Nested field |
| `connection.uris[0]` | First element of array |
| `connection.uris[1]` | Second element of array |

### Examples

```bash
# Get the hostname
garden-rake config mongodb --field connection.hostname
# Output: oak.local

# Get the first URI (hostname-based)
garden-rake config mongodb --field connection.uris[0]
# Output: mongodb://oak.local:27017

# Get the second URI (IP-based)
garden-rake config mongodb --field connection.uris[1]
# Output: mongodb://10.0.0.5:27017

# Get the port as a number
garden-rake config mongodb --field connection.port
# Output: 27017
```

## The `find` Command

The `find` command also supports automation modes:

```bash
# JSON output with all matches
garden-rake find mongodb --output json

# Get just the connection URI
garden-rake find mongodb --format uri

# Get the IP-based URI
garden-rake find mongodb --format uri-ip
```

## Scripting Examples

### Bash

```bash
#!/bin/bash

# Get MongoDB URI for connection string
MONGO_URI=$(garden-rake config mongodb --field connection.uri)
echo "Connecting to: $MONGO_URI"

# Use in application config
export DATABASE_URL="$MONGO_URI/mydb"

# Check if service exists (exit code)
if garden-rake config mongodb --field name > /dev/null 2>&1; then
    echo "MongoDB is available"
else
    echo "MongoDB not found"
    exit 1
fi
```

### PowerShell

```powershell
# Get MongoDB URI
$mongoUri = garden-rake config mongodb --field connection.uri

# Parse JSON output
$config = garden-rake config mongodb --output json | ConvertFrom-Json
Write-Host "Service running on: $($config.stone.name)"
Write-Host "Port: $($config.connection.port)"
```

### Docker Compose Integration

```yaml
# docker-compose.yml
services:
  myapp:
    image: myapp:latest
    environment:
      - DATABASE_URL=${DATABASE_URL}

# .env file generated by script
# DATABASE_URL=$(garden-rake config mongodb --field connection.uri)/mydb
```

### CI/CD Pipeline

```yaml
# GitHub Actions example
jobs:
  deploy:
    steps:
      - name: Get service config
        run: |
          REDIS_HOST=$(garden-rake config redis --field connection.hostname)
          REDIS_PORT=$(garden-rake config redis --field connection.port)
          echo "REDIS_URL=redis://${REDIS_HOST}:${REDIS_PORT}" >> $GITHUB_ENV
```

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | Service not found or field not found |
| Non-zero | Other errors (connection, API, etc.) |

When using `--field` or `--output json`, error messages go to stderr, keeping stdout clean for parsing.

## Best Practices

1. **Use `--field` for single values** — Avoids parsing JSON in shell scripts
2. **Use `--output json` for complex data** — When you need multiple fields
3. **Use `-q` in scripts** — Suppresses hints that could pollute output
4. **Check exit codes** — Service not found returns exit code 1
5. **Prefer hostname URIs** — `connection.uris[0]` uses hostnames; `connection.uris[1]` uses IPs
