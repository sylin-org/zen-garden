# ORCH-0034: Provider Resolution Metadata

**Date**: 2026-04-10
**Status**: Accepted
**Deciders**: Leo
**Related ADRs**:
- ORCH-0028 (orchestrator core) — defines the `Provider` trait this ADR extends
- ORCH-0030 (architecture realignment) — defines the lean three-method trait
- ORCH-0033 (request log) — consumes the metadata for persistent records

---

## Context

The `Provider` trait's `onboard` method returns
`Result<ProviderOutcome, ProviderError>`. `ProviderOutcome` carries the
output data but nothing about how the provider produced it.

At `onboard` time, the adapter holds resolution context that no other
component has:

| Provider knows | Dispatcher gets | Current state |
|---|---|---|
| Which model it resolved to | Nothing | `_meta.model` is always `None` |
| Which instance served the request | Nothing | Lost after return |
| Which stone it ran on | Nothing | Lost |
| Token usage (input/output) | Sometimes (buried in output Value) | Inconsistent extraction |
| A domain-meaningful summary | Nothing | The frontend guesses from raw input |

The HTTP response `_meta.model` field has been `None` since ORCH-0030
R2 M3 made model resolution adapter-local. The persistent request log
(ORCH-0033) has empty `meta.model` and `meta.stone` fields. The
dashboard history panel has no way to show what answered or generate
a meaningful one-liner without client-side heuristics that break across
action types.

---

## Decision

### `ProviderMeta` — structured resolution metadata

A new struct returned alongside the outcome. Every field is optional —
adapters populate what they know.

```rust
#[derive(Debug, Clone, Default, Serialize)]
pub struct ProviderMeta {
    /// The model actually used (adapter-resolved).
    /// E.g. "gemma3:12b", "animij.safetensors".
    pub model: Option<String>,

    /// The instance URL that served the request.
    /// E.g. "http://stone-azure-pool:11434".
    pub instance: Option<String>,

    /// The stone name the instance runs on.
    /// E.g. "stone-azure-pool".
    pub stone: Option<String>,

    /// Input token count, if tracked by the provider.
    pub tokens_in: Option<u64>,

    /// Output token count, if tracked by the provider.
    pub tokens_out: Option<u64>,

    /// Human-readable one-liner summarizing the interaction.
    /// Generated by the adapter from its domain knowledge of the
    /// action, input, and output.
    ///
    /// Examples:
    ///   "Translate: 'Good mo...' en→es"
    ///   "Chat: 'What is...' → 'Paris is...'"
    ///   "Generate: animij 'a cat in...'"
    ///   "Transcribe: 3m42s → 'The quick...'"
    ///   "Embed: 3 inputs, 384 dims"
    pub summary: Option<String>,
}
```

### `ProviderResult` — wraps outcome + meta

```rust
pub struct ProviderResult {
    pub outcome: ProviderOutcome,
    pub meta: ProviderMeta,
}
```

### Trait change

```rust
#[async_trait]
pub trait Provider: Send + Sync + 'static {
    fn name(&self) -> ProviderName;

    async fn onboard(
        &self,
        request: OrchestratorRequest,
    ) -> Result<ProviderResult, ProviderError>;  // was ProviderOutcome

    async fn flush_caches(&self) -> Result<FlushReport, ProviderError> {
        Ok(FlushReport::empty())
    }
}
```

### Adapter changes

Each adapter wraps its existing return in `ProviderResult` and
populates whichever fields it has in scope at return time. Most
adapters already hold the model name, instance URL, and token counts
in local variables — they just weren't returning them.

Adapters that don't track a field leave it `None`. No adapter is
forced to generate a summary — but those that do produce
domain-specific one-liners.

Summary examples per primitive:

| Primitive | Summary format |
|-----------|---------------|
| `text.chat` | `"'What is the...' → 'Paris is the...'"` |
| `text.translate` | `"'Good morning' en→es"` |
| `text.embed` | `"3 inputs, 384 dims"` |
| `image.generate` | `"animij: 'a cat in a garden...'"` |
| `image.analyze` | `"'What breed...' → 'Golden Retriever'"` |
| `audio.generate` | `"'Good evening' [af_heart]"` |
| `audio.transcribe` | `"→ 'The quick brown fox...'"` |

### Downstream consumers

**Dispatcher** (services/dispatcher.rs):
- Reads `result.meta` and passes it to `request_store.complete()`
- Populates `PersistedRequest.meta` with model, stone, tokens, summary

**HTTP envelope** (http/envelopes.rs):
- `_meta.model` populated from `result.meta.model` (no longer `None`)
- `_meta.instance` optionally exposed

**Request log** (domain/persisted_request.rs):
- `meta.model`, `meta.stone`, `meta.summary` populated from provider
- History panel renders `summary` directly — one line, no heuristics

**Dashboard history**:
- Renders `summary` if present, falls back to action name if not
- Relative timestamp (`12s`, `4m`, `2h`, `1d`)

---

## Consequences

### Positive

- **Model attribution restored.** Every response tells the user what
  model answered — lost since ORCH-0030 R2 M3.
- **Adapter-owned summaries.** Each provider generates summaries from
  domain knowledge, not generic frontend guessing.
- **Single source of truth.** Resolution metadata flows from provider
  → dispatcher → request record → HTTP envelope → dashboard. No
  duplication, no divergence.

### Negative

- **Trait change touches every adapter.** Mechanical but wide — every
  `onboard` return site needs wrapping. Mitigated by `ProviderMeta::default()`
  making the minimum change a one-line wrap.
