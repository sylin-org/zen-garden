# 07 — Rake CLI Contract: One Grammar, One Output, One Exit Code

> Scripts can trust rake: every failure exits non-zero, `-o json` works everywhere or nowhere, every help
> example parses, and the four output systems become one. Phase: Truth. Depends on: 02. Feeds: 14 (the
> resolver needs a trustworthy CLI substrate).

## Mission

Rake's skeleton is excellent — manifest-driven command generation, a 4-level connection cascade, retry
with cache-flush — but its *contract* is unreliable: 25 of 130 help examples are rejected by the parser
they document, `pond join` failure exits 0, `find` calls `process::exit` mid-function, exactly 3 of 36
commands honor the global `-o json`, and four output systems coexist (one with zero uses). For an
audience of first-time builders and automation users, the contract IS the product. Rebuild it greenfield:
no compat with the old inconsistencies.

## Plan gate — OPERATOR decisions

1. **JSON scope**: every *read* command emits `-o json` (recommended), or remove the global flag and add
   it per-command. Mutating commands: recommend a uniform `{"success":bool,"message":str,...}` envelope.
2. **Homonym resolution** (recommend, but vocabulary is the maintainer's voice): `stone wake` → `stone
   rouse` or keep and document; `storage release` → `storage unmount`; merge `store`/`backup` under
   `storage`. Present a rename table, get sign-off — these are breaking renames and greenfield rules say
   do them now, once.

## Target shape

Exit-code contract (document in `docs/reference/cli-contract.md`, generate nothing — write ~40 lines):

```
0 success | 1 operation failed (server said no / not found) | 2 usage error (clap)
3 connection failed (no stone reachable) | 4 auth required (per prompt 05)
```

One top-level mapper; command bodies NEVER call `process::exit` and NEVER print-then-`Ok(())`:

```rust
// main.rs — the only exit point
match route(cmd, ctx).await {
    Ok(()) => ExitCode::SUCCESS,
    Err(e) => { render_error(&e, &ctx); e.exit_code() }   // RakeError enum, typed per code-standards §10
}
```

One output pipeline (delete OutputWriter or make it this; merge CliFormatter+Layout into it):

```rust
ctx.out.table(headers, rows)?;      // human: aligned, colored; json: array of objects
ctx.out.kv("Stone", &stone.name)?;  // human: "Stone  oak"; json: {"stone":"oak"}
ctx.out.result(&payload)?;          // the -o json envelope for the whole command
```

The example-integrity test (the heart of this prompt — CI runs it forever after):

```rust
#[test]
fn every_manifest_example_parses() {
    let app = build_clap_app();
    for (cmd, example) in manifest_examples() {
        let argv = shell_words::split(example).unwrap();
        app.clone().try_get_matches_from(argv)
            .unwrap_or_else(|e| panic!("manifest example for `{cmd}` no longer parses: {example}\n{e}"));
    }
}
```

## Implementation

1. The example test first (RED: it fails on 25). Fix the 23 natural-language examples to flag form and
   the 2 dead flags. Keep the intentional trailing-word grammars — add them to the test's allowlist with
   a comment, or better, encode their grammar in the manifest so the test needs no allowlist.
2. `RakeError` enum + exit-code mapper; convert `pond.rs`'s three `Ok(())`-after-eprintln sites and
   `find.rs`'s five `process::exit` sites; sweep the remaining commands
   (`grep -rn "process::exit" src/rake/src` must end empty except main).
3. Output pipeline: build the unified writer; migrate commands family-by-family (storage → services →
   offerings → pond → the rest), deleting raw `println!`s as you go. `-o json` per the OPERATOR decision.
4. Finish the StoneApi migration for the 12 raw-HTTP files (fix `list.rs`'s missing status check first).
5. Homonym renames per sign-off: manifest + route + docs references in `docs/guides/rake-automation.md`.
6. Update `rake-automation.md` to the now-true contract (exit codes, JSON, examples).
7. Commit per step; run `cargo test -p garden-rake` after each.
